# Инструменты и локальное окружение

Открывай при выборе стека, зависимостей, настройке окружения или восстановлении рабочего окружения. Конкретные команды и версии бери из проекта.

## Предпочтения для разработки

Повторяемые правила форматирования, типов и проверки закрепляй в инструментах проекта. Для частого сценария полезна одна понятная команда с рабочими значениями по умолчанию и объяснимой ошибкой. AGENTS.md связывает задачу с действующей командой и существенной особенностью; настройки и скрипты остаются источником точной механики. При изменении, затрагивающем воспроизводимость, зависимости или запуск, проверь нужный сценарий в известном чистом или изолированном состоянии; для локальной настройки достаточно затронутой проверки.

- Сохраняй текущий стек, manifest и lockfile. Если проект не задаёт стек и задача требует нового выбора, сравни поддерживаемые варианты по требованиям, совместимости и стоимости; `uv`, `pytest`, `pyright` и `tyro` — примеры для нового Python-проекта, а не обязательная замена. В uv-проекте используй `uv add` для зависимостей и `uv run` для запуска, сохраняя согласованность manifest и lockfile. В CI устанавливай зафиксированные зависимости; обновление lockfile выполняй как явное изменение.
- При ошибке доступа именно к uv cache используй доступный cache проекта, например `UV_CACHE_DIR=.uv-cache uv run ...`. Для других ограничений найди разрешённый путь или запроси конкретно необходимый доступ через механизм среды. Ожидаемую интерактивную команду продолжай в рамках уже полученного разрешения.
- Для новых JS/TS-проектов предпочитай TypeScript; в существующем JavaScript используй JSDoc, когда миграция не входит в задачу. Выбирай явные импорты по правилам проекта, содержательные имена и единицы измерения констант. Изменяемое состояние принадлежит компоненту; I/O запускается на явном этапе жизненного цикла.
- Фреймворк выбирай по требованиям и поддержке: например, FastAPI/Uvicorn могут подходить Python HTTP-сервису. Для конкурентности используй гарантии из [руководства состояния](runtime.md); сравнивай операционную нагрузку собственного сервиса с ресурсом команды. Новизна инструмента имеет смысл вместе с конкретной пользой и приемлемой стоимостью перехода.

## Продолжение после прерванной работы

Считай прерванную задачу частично выполненной: проверь локальные файлы и `git status` в репозитории, затем продолжай от сохранённого состояния небольшими проверяемыми шагами. Инструкции восстановления конкретной машины бери из её документации.
